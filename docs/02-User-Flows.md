# User Flows（Mera-first）

> 设计原则：一次 Passkey 仪式完成注册；之后在 Signing Session 有效期内支付可无感；必须通过 Stateless Test。

---

## 1. 新用户首次注册（One-prompt Onboarding）

```
打开网站 / App（落地页）
        │
        ▼
┌─────────────────────────────────────┐
│              登录 / 开始页            │
│                                     │
│     [ 用 Face ID / 指纹开始 ]        │  ← 唯一主按钮
│                                     │
│   小字：无种子短语 · 自托管 · 安全   │
└─────────────────────────────────────┘
        │ 用户点击
        ▼
系统调用 Mera：createPasskeyWithPrfOutput
（浏览器弹出系统生物识别 / 安全密钥确认）
        │ 用户通过 Face ID / 指纹
        ▼
获得 prfOutput → 派生 BIP-44 EOA
创建 Mera Signing Session（设定 scope 与过期时间）
        │
        ▼
直接进入首页（显示地址、余额）
可选：自动触发或引导完成第一笔小额操作（冲 Time-to-first-transaction）
```

**关键要求**：
- 只有一次 Passkey 仪式
- 无 Google/GitHub/邮箱/OTP 强制步骤
- 无种子短语展示
- 无钱包扩展安装

---

## 2. 支付 / 转账流程（含 Session）

```
用户进入支付页
输入收款地址 / 扫码 + 金额
点击「确认支付」
        │
        ▼
检查当前 Mera Signing Session 是否有效
        │
   ┌────┴────────────────────┐
   │ Session 有效             │ Session 已过期 / 不存在
   ▼                         ▼
直接使用 Session           弹出生物识别
进行 prompt-free 签名       重新创建 Session 后再签名
   │                         │
   └────────────┬────────────┘
                ▼
发送交易到 Monad
                ▼
快速确认（利用 300ms 出块）
显示「支付成功」+ 更新余额与历史
```

**Session 设计建议**：
- 有效期：5–15 分钟（演示时可调整）
- Scope：允许转账 / Swap，可设单笔或累计金额上限
- 过期提示文案清晰：「会话已过期，请再次验证以继续」

---

## 3. 简单 Swap 流程

与支付流程相同，共用同一套 Session 判断逻辑。  
会话有效期内可连续完成多笔操作而不重复弹生物识别。

---

## 4. 老用户回访 / 跨设备（Stateless 友好）

```
打开 App（可能是新设备、无痕模式、或已清除 localStorage）
        │
        ▼
显示「用 Face ID / 指纹继续」
        │ 用户点击
        ▼
系统通过 WebAuthn 找到已有 Passkey（或让用户选择）
Mera 再次通过 PRF 得到相同 prfOutput
派生出相同 EOA 地址
创建新的 Signing Session
        │
        ▼
完整恢复账户访问（地址、余额、历史均可重新拉取）
```

**这就是 Stateless Test 的通过路径**：  
不依赖 localStorage 里的敏感数据，只靠用户持有的 Passkey 即可重建一切。

---

## 5. 会话过期与重新验证

```
用户在 Session 过期后尝试支付
        │
        ▼
UI 提示「为了安全，请再次验证」
        │
        ▼
弹出生物识别 → 成功后刷新 Session
        │
        ▼
继续完成支付（无需重新输入金额等信息）
```

---

## 6. 可选高级操作

- **导出恢复方式**（高级设置）：可生成助记词供用户备份到 MetaMask 等，但默认路径不引导
- **查看当前 Session 状态**：剩余有效时间、权限范围
- **主动结束 Session**：用户可手动锁定

---

## 7. 异常与边界

| 情况 | 处理 |
|------|------|
| 用户取消生物识别 | 提示「已取消」，可重试，不中断流程上下文 |
| 设备不支持 PRF / Passkey | 明确提示当前设备不支持，建议更换设备或使用支持的浏览器 |
| 交易失败 | 清晰错误 + 重试，Session 状态保持 |
| 网络问题 | 加载与重试状态友好 |

---

## 8. 与 Mera 评测标准的对应

| 评测点 | 本流程如何满足 |
|--------|----------------|
| Time-to-first-transaction | 落地页 → 一次生物识别 → 直接进入并尽快完成首笔交易 |
| One-prompt onboarding | 仅一次 Passkey 仪式 |
| Session design | 明确区分 prompt-free 与需重新验证的操作，过期体验清晰 |
| Stateless test | 清存储或换设备后，只靠 Passkey 完整重建 |
| 用户几乎感觉不到区块链 | 无种子短语、无扩展、无复杂链上概念暴露 |
