# Flowpay 市场推广与用户获取策略

## 1. 定位与切入点
Flowpay 不与微信/支付宝争夺全体线下 SMB，而切入「本来就要收 USDC / 稳定币的当面场景」：跨境小店、工作室、会展摊位、加密社区线下活动、以及已有 USDC 往来的小商户。核心承诺是：店员约两分钟能独立收款，顾客扫码到成功尽量在半分钟内完成，尽量不谈种子短语与链概念。

传播叙事统一为三句话：Passkey 即账户；当面扫码收 USDC；流水可导出对账。避免把 Swap、多链钱包或「下一个超级 App」当作获客钩子。

## 2. 早期用户从哪里来（0→100）
第一阶段目标不是规模广告，而是可验证的试用闭环。

1）黑客松与 Monad / Mera 生态活动：用可运行产品与双设备演示换评委、builder、生态 BD 的注意力；提交包、Demo 视频与公开部署降低「看不懂」成本。
2）加密线下局与社区：在已有 USDC 收付习惯的社群、Maker/Builder meetup、高校黑客松周边，提供「摊位收款」试运行——现场帮商户完成开户与第一笔小额收款。
3）设计伙伴（Design partners）：优先找 3–10 个真实有当面 USDC 需求的商户/摊主，用测试网先跑流程熟练度与话术，再随主网成熟迁移；成功标准是「下周还愿意用」，而不是下载量。
4）内容获客（轻量）：短视频/图文只讲一个完整故事——「顾客刷脸付 USDC，老板听到到账声」。每条内容带演示链接与「需要真机 Passkey」的诚实说明，过滤不匹配流量。

## 3. 激活与留存（试用如何变成习惯）
激活路径压成最短：Passkey 开户 → 收银台出码 → 对端付款 → 到账与导出。首次成功比功能广度重要。

留存靠「当日流水可核对」：老板能看见笔数、总额、交易哈希，并能导出 CSV。服务侧用检查清单（设备是否支持 PRF、水龙头、超时重开单）降低现场翻车。对失败态（超时、余额不足、Gas 不足）保持可读文案，避免假成功。

Session 用于降低重复验证摩擦，但不拿「无感链上」过度承诺；Stateless 恢复作为信任证明：换机/清缓存仍可找回，适合演示与口碑。

## 4. 增长杠杆（100→1000，原则性）
在测试网阶段，增长以「可演示密度」和「商户转介绍」为主，而不是付费投放。

- 活动型增长：会展、市集、主题市集的「稳定币收款位」；与钱包/生态方联合摆摊日。
- 转介绍：设计伙伴成功后，请其介绍同类商户；提供一页上手指南与现场 checklist，降低转介绍成本。
- 生态分发：作为 Mera / Monad 示例应用出现在文档、showcase、bounty 相关列表；保持仓库与演示长期可访问。
- 产品驱动：把「出码—到账—导出」做到比口头解释更快；任何新增功能若拉长首次成功路径，默认不做获客主推。

付费获客仅在确认主网可用资金流、Gas 对顾客基本不可见、且至少有留存商户后评估；当前不把烧钱获客写入必做路径。

## 5. 渠道与材料
对外统一入口：生产演示站、GitHub、黑客松提交文档与 Demo 视频。对商户话术避免 RPC、助记词、账户抽象；对开发者/评委话术强调 Mera 账户层、自托管与 Stateless。中英文材料并存时，以收银主线一致为准（Swap 不作为获客卖点）。

## 6. 指标与节奏
近端指标：完成双设备首单的商户数；7 日内回访商户数；丢单/假成功事故数（目标为零）；从打开到首笔成功的中位时长。
远端指标（主网后）：周活跃收款商户、笔均金额、导出使用率、转介绍占比。

节奏建议：黑客松期以演示转化与设计伙伴签约意向为主；其后 2–4 周做测试网稳定性与话术打磨；主网条件成熟再谈规模化投放。

## 7. 风险与诚实边界
WebAuthn PRF 设备覆盖有限，获客文案必须写清推荐机型，避免「所有手机都能用」的虚假承诺。Gas 赞助未就绪前，不把「零 Gas」当广告词。不把黑客松流量等同于产品市场契合；真正 PMF 信号是商户自愿回访与愿意介绍同行。
